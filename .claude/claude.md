# Project Guidelines

## General development practises

When starting a task, always check you are working on a branch, since we will never push straight to main in this repo. Do a `git checkout -b` as required with a suitable branch name.


## Git & PR Workflow

When asked to submit a PR:
1. Stage and commit changes with a brief, descriptive commit message (1-2 sentences max)
2. Push the branch and open a PR using `gh pr create`
3. Keep PR descriptions concise - summarize what changed and why. Don't go into details such as creating "testing plan" checkboxes.
